# Interop/Aeneas

Rust code in VCVio: programs that hax and Aeneas extract from Rust crates, in Aeneas's monad
`RustM`, lifted into `OracleComp` and specified with core's `Std.WP` triples. It is the first
sub-project of [`Interop/`](../README.md), whose index states the rules all sub-projects share.

## Connects to

- **hax 0.5**: [`cryspen/hax`](https://github.com/cryspen/hax) at `a045d15a`, tagged
  `cargo-hax-v0.5.0`.
  The package requires hax's Lean library (`hax-lib/proof-libs/lean`); the example crates depend on
  `hax-lib` at the same commit (`Hax/Cargo.toml`), and extraction needs `cargo-hax` at that commit.
- **Aeneas**: the fork [`dtumad/aeneas`](https://github.com/dtumad/aeneas) at `1e414a54`
  (`backends/lean`). It combines hax's `RustM` interface with the upstream Lean 4.36 fixes for enum
  declarations and scalar set-membership rules
  ([Aeneas Lean update](https://github.com/AeneasVerif/aeneas/pull/1547)). The override can be
  removed when hax pins a compatible backend.
- **Lean and Mathlib** v4.36.0, the root's pins, so the sub-project shares the root's dependency
  cache.

hax and Aeneas emit code in one monad, `Aeneas.Std.RustM`. hax's Lean library builds on Aeneas's,
and the fork of Aeneas it pins names it `RustM`; upstream Aeneas calls the same definition `Result`.
- It is an interaction tree over Aeneas's effect `RustEffect`, from Aeneas's own coinductive
  library.
- That effect's only event is `fail e`, with no answer. So a `RustM` computation unfolds in one step
  to a returned value, a failure or divergence, and one lift serves both tools.

## Trusted base

- **The translation.** hax 0.5's Lean output goes through Charon and Aeneas: hax's frontend reads the
  crate, Charon translates it, and Aeneas emits the Lean modules. All three are trusted to preserve
  the crate's meaning.
- **The Rust models.** The definitions in Aeneas's `Aeneas.Std` and in hax's Lean library (its
  scalar operations, `core` models and contract encoding) are trusted to model Rust.
- **How outside code enters.** The extracted modules, `Hax/<Name>/Extraction/`, are generated by
  `scripts/regenerate-hax.sh` and committed, so building this sub-project needs no Rust. CI's
  `hax Extraction` workflow (`.github/workflows/hax-extraction.yml`) extracts them afresh with the
  pinned `cargo-hax` and fails if a committed module differs. See [the hax examples](Hax/README.md).

## Assumptions

- A Rust function means its extracted `RustM` program; nothing in Lean refers to the Rust source.
- A `RustM` program returns, fails with an `Aeneas.Std.Error` or diverges. Aeneas's scalar
  operations fail with a panic on overflow and on division by zero. The lift sends a failure to
  `RustOracleComp`'s `ExceptT Error` layer and divergence to its `OptionT` layer; oracle queries
  come only from the VCVio side.
- A crate's `#[requires]` and `#[ensures]` contract means the clauses hax extracts, `f.pre` and
  `f.post`, and the contract `f.spec`.
- External Rust definitions are modelled by hand in `Extraction/FunsExternal.lean` and
  `TypesExternal.lean`; none of the examples has any.

## Implementations covered

The crates in `Hax/`, each extracted by the hax CLI and proved in VCVio:

| Example | Shows |
|---|---|
| `CenteredBinomial` | ML-KEM's CBD(η = 1) step: its contract that the result is `-1`, `0` or `1`, its exact distribution, and its possible values by core's `vcgen` |
| `Barrett` | ML-KEM's signed Barrett reduction modulo 3329: the result is reduced and congruent to the input, by hax's own proof |
| `Adc` | 32-bit add-with-carry, the multi-precision building block, by hax's own proof |
| `Computation` | `x + x + 1` from hax's Lean test suite, without overflow |
| `Division` | checked `/`: the quotient for a nonzero divisor, a panic for zero, and a panic probability of `1/2` under a uniform bit |
| `Examples` | a Rust addition after an oracle query, specified over every possible answer |

`Adc` and `Barrett` are vendored from hax's examples, with provenance.

## What is proved

| Module | Content |
|---|---|
| `Interop.Aeneas.Lift.Common` | `RustOracleComp spec α := ExceptT Error (OptionT (OracleComp spec)) α`: Rust panics, then divergence, then oracle queries |
| `Interop.Aeneas.Lift.Run` | `.run.run` equations for that stack, for probabilistic proofs |
| `Interop.Aeneas.Lift.RustM` | the lift `RustM → RustOracleComp spec`, with its `pure`/`bind` laws, `LawfulMonadLift` and a bundled `MonadHom` |
| `Interop.Aeneas.Lift.Triple` | Aeneas's specifications (`spec`, `dspec`, `Std.Do` triples, and the implication form of hax's extracted contracts) as `Std.WP` triples for the lift, under any interpretation of `OracleComp spec`, and the `vcgen` rule `Spec.liftRustM` |
| `Interop.Aeneas.ITree` | Aeneas's interaction trees as PolyFun's: an injective monad morphism into `ITree ⟨E.I, E.O⟩`, sending `div` to `ITree.diverge` |
| `Interop.Aeneas.WP` | Aeneas's total and partial correctness (`DWP`, `DWLP`) are PolyFun's `ITree.wpTotal` and `ITree.wpPartial` along `toPolyFun`, for every Aeneas effect, with exact `bind` laws as corollaries |
| `Interop.Aeneas.Hax.Holds` | hax's extracted `requires` and `ensures` clauses, read as plain propositions |
| `Interop.Aeneas.Hax.<Name>.Verification` | the results listed under *Implementations covered*: each contract, its clauses in plain arithmetic, and the lifted program's `Std.WP` triple |

A `Std.WP` contract for `RustOracleComp` can specify each exception channel by type.
`throws (e : Interop.Rust.Error) => …` describes a panic and `throws (u : Unit) => …` describes
divergence. The [Lean example](Hax/Examples/Verification.lean) uses different postconditions for
the two exits under an arbitrary interpretation of oracle queries. Its caller applies the generated
`panicOrDiverge.spec` theorem directly. On Lean 4.36, bare `vcgen` fails to reconstruct this
two-slot rule at a call site.

The declarations are in the namespaces `Interop.Rust` (the lift), `Aeneas.Data.Coinductive` (the
interaction-tree bridges) and `Interop.Hax` (the examples). CI's axiom sweep holds every root of
`InteropAeneas` at zero `sorry` and nonstandard-axiom debt.

## Stability

Beyond the [stability](../README.md#stability) of `Interop/`, this sub-project follows hax and
Aeneas: their Lean output and libraries change between releases, and the lift, the triples and the
extractions change with them. The pins move together with `lake update hax mathlib`, run in this
directory and never as a bare `lake update`, and then the extractions are regenerated.

## Build and test

```bash
cd Interop/Aeneas
lake exe cache get
lake build      # VCVio, hax, Aeneas, and the library InteropAeneas
```

The library `InteropAeneas` lists the roots, and the extracted modules form the library
`InteropAeneasHaxExtraction`. The examples are proofs that `lake build` checks, so the package has
no test driver. CI's `Interop Aeneas` job builds the package and sweeps the roots of
`InteropAeneas` for axioms; [the hax examples](Hax/README.md) describe regenerating the
extractions and adding an example.
